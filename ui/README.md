# ui/ — 발표용 대시보드·STT·TTS·결과 보고서

담당: UI·문서 세션. 다른 세션은 읽기만 한다(고칠 곳은 [막힘] 으로).

## 실행

```bash
cd ~/dev/projects/ball-sorter
ui/start_ui.sh                       # systemd-run --user 로 띄움(SSH 가 끊겨도 산다), 로그 ui/ui.log
# 브라우저(젠북): http://127.0.0.1:7870      어두운 화면이 싫으면 ?__theme=light
systemctl --user stop ball-ui        # 끄기
```

- 포트 7870(7860 은 Physical AI Studio 백엔드가 쓴다). 127.0.0.1 에만 바인드.
- 바로 실행: `.venv/bin/python -m ui.app` (프로젝트 루트에서).
- 시연 리허설: `UI_AGENT=fake ui/start_ui.sh` = 에이전트 없이 가짜 스트림으로 화면만.
- 에이전트 + 가짜 작업대(밤·하드웨어 없이): `UI_TTS_OUT=silent BALL_MOCK=1 BALL_MOCK_POLICY_S=2 ui/start_ui.sh`
- 실제 로봇(사용자 입회 때만): `BALL_ROBOT=1 ui/start_ui.sh` — 이때는 셸에 BALL_MOCK 이 있어도 넘기지 않는다. 머리줄 배지가 "로봇 실물"인지 본다(`BALL_ROBOT=dry` 면 "로봇 시험(안 움직임)").
- `start_ui.sh` 는 지금 셸의 `UI_* FAKE_* BALL_* TTS_* STT_* LLM_* EMB_* RERANK_*` 를 전부 유닛에 넘기고, 넘긴 목록을 첫 줄에 찍는다. 유닛 환경 확인: `systemctl --user show ball-ui -p Environment`.

### 오프라인 (와이파이 끄고 리허설·시연)

- **서버(파이썬) 쪽 — 막는다.** `ui/netguard.py` 가 gradio·에이전트를 불러오기 전에 감사 훅(`sys.addaudithook`)을 건다. 이 프로세스(대시보드 + 같은 프로세스에서 도는 에이전트·gradio·라이브러리)의 `getaddrinfo`·`connect`·`sendto` 가 루프백(127.0.0.0/8·::1·localhost)이 아니면 "이름 풀이 실패/네트워크 없음"으로 바로 실패시킨다 = 와이파이를 끈 것과 같은 동작이 와이파이가 켜져 있어도 난다. 막은 건수는 머리줄 배지("외부 접속 0건" / "외부 접속 차단 N건")와 로그(`net`), `ui/ui.log`(`[netguard]`)에 남고, 보고서 배지도 0건일 때만 "외부 API 호출 0건"이다.
- 그 위에 기본값으로 끈 것: Gradio 분석·버전 확인(`GRADIO_ANALYTICS_ENABLED=False`), 허깅페이스(`HF_HUB_OFFLINE=1`·`HF_HUB_DISABLE_TELEMETRY=1`, `tts.py` 도 따로 설정), Supertonic 모델 내려받기(`auto_download=False`). 에이전트는 Chroma 텔레메트리를 끈다(`agent/config.py`).
- **브라우저 쪽 — 전부 로컬 자원.** 글꼴은 시스템 글꼴(Noto Sans CJK KR·NanumGothicCoding)만 지정해 Google Fonts 를 안 부른다. Gradio 프런트엔드 `index.html` 의 외부 주소는 `og:image`·`og:url` 메타뿐이라 요청이 없다. 보고서 HTML 은 CSS·사진을 안에 담아 외부 링크 0개.
- 확인(10-21 밤): 크롬을 `--host-resolver-rules`(127.0.0.1 말고 이름 풀이 실패)로 띄워 명령 1→5·질문·멈춤 — 외부 요청 0·콘솔 오류 0·화면 정상, 서버 쪽 차단 0건. 파이썬 쪽 차단 시험: requests·httpx·urllib·UDP 로 바깥(api.gradio.app·huggingface.co·1.1.1.1·8.8.8.8)은 0.00~0.02초에 실패, 127.0.0.1/localhost:8100 은 정상.
- 젠북 와이파이를 실제로 끄는 시험은 안 했다(원격으로 붙어 있어 끄면 끊긴다). 내일 끄면 머리줄 "와이파이 꺼짐" 배지가 초록으로 바뀐다.

### 보기 전용 화면 (`UI_VIEW=1`, 10-23 발표 — 교육장 사람들이 각자 노트북·폰으로)

- 켜기: `UI_VIEW=1 ui/start_ui.sh`(지금 셸의 `UI_*` 를 그대로 넘긴다 — 실물이면 `UI_VIEW=1 BALL_ROBOT=1 BALL_COORD=1 ui/start_ui.sh`). 주소는 시작 로그(`ui/ui.log` 의 "보기 전용 화면: http://192.168.0.x:7880/v/<토큰>", 화면 로그)와 머리줄 배지 "보기 전용 <주소> · N명"(지난 5초에 본 브라우저 수). 토큰은 켤 때마다 무작위 8자(l·o·0·1 뺌).
- 대시보드(Gradio)는 로그인이 없어 그대로 127.0.0.1:7870. 밖에 여는 것은 `ui/view.py` 의 표준 라이브러리 HTTP 서버(스레드, 0.0.0.0:7880) 하나이고, 경로는 GET `/v/<토큰>`(페이지)·`/v/<토큰>/s`(구역별 HTML 조각 JSON, 1초마다)·`/v/<토큰>/snap`(지금 위 카메라 사진 — 경로를 받지 않고 대시보드가 보이는 그 파일만 읽음) 셋뿐. 그 밖의 경로와 GET 이 아닌 모든 메서드(POST·PUT·HEAD·OPTIONS …)는 404. 입력칸·버튼·마이크·링크·Gradio API 없음.
- 보이는 것(대시보드와 같은 `html_*` 조각): 머리줄·위 카메라 사진·현재 배치 그림·개수 카드·LangGraph 노드·명령 결과(명령 글 → 결과 문구)·대화(글자만, 태그는 벗김)·로그·디바이스 표·결과 보고서(`sandbox` iframe). 폰(640px 아래)은 한 줄로 쌓고 카드는 2칸, 가로 스크롤 없음. 글꼴은 시스템 글꼴, 응답마다 `Content-Security-Policy`(`default-src 'none'`, 같은 서버만) 라 외부 요청 0.
- 시연을 깨지 않게: BOARD 는 잠금 안에서 `deepcopy` 만 하고 바로 놓는다(약 0.7ms), 그리기는 잠금 밖에서 그 복사본으로(`view_sections` 가 이 모듈 함수들을 BOARD 만 복사본인 이름표에 다시 묶어 부름 — 대시보드의 카드 강조·로그를 안 건드림). 렌더는 손님 수와 상관없이 1초에 한 번을 캐시해 나눠 주고, 브라우저가 가진 구역 지문(`?h=`)과 같은 구역은 빼고 보낸다(gzip). 서버 예외는 스레드 안에서 전부 잡아 로그 한 줄(`view`, 같은 종류 60초에 한 번), 폰 접속 끊김은 조용히. 포트를 못 열면 로그 "보기 전용 화면 못 엶 … — 대시보드는 그대로" 만 남기고 대시보드는 뜬다.
- 방화벽(젠북 ufw active): `sudo ufw allow in on wlo1 from 192.168.0.0/24 to any port 7880 proto tcp comment 'ball-sorter view'`. 발표가 끝나면 `sudo ufw delete allow in on wlo1 from 192.168.0.0/24 to any port 7880 proto tcp`.

- **현재 배치**(10-21 밤): 위에서 본 작업대 그림 — 투입 구역(3×3 칸), 분홍·초록·불량 그릇, 손 자리. `detect_objects` 결과에 `objects`(블록마다 `zone`·`cell`)가 있으면 블록을 그 칸에 색 네모로(분홍·초록, 불량은 검은 X) 찍고, 없으면(옛 형식) 구역마다 개수만 쓴다. `zone` 이 5구역이 아니면 "구역 밖 n개". 손이 보이면 손 자리가 칠해진다. 마지막 detect 결과를 그대로 그린다(배치 질문·정책 전후·보고 때마다 바뀜).
- **위치 단서**(10-23): "왼쪽 초록 블록 옮겨 줘"처럼 위치를 말하면(`which` = left·right·middle, 에이전트 RESULT 14절) 투입 구역 안 그 쪽에 짧은 표 — 왼쪽 위 "◀ 왼쪽", 가운데 "▼ 가운데", 오른쪽 위 "오른쪽 ▶" — 와 그림 아래 "위치 왼쪽". 위치로 고르지 못해 거부되면(로봇 함수에 `which` 인자 없음·ACT 방식·위치 둘) 점선 주황 "⊘ 왼쪽"·"⊘ 위치 둘". 위치 단서가 없는 명령에는 안 보인다. 다음 명령이 오면 지운다. 시작 로그에 `agent.get_method()` 의 방식·위치로 고르기 됨/안 됨.
- **위치·관계**(10-23 13:30, RESULT 19절): `which` 에 top·bottom·near·far, 새 `next_to`(red·blue·red_defect·blue_defect). 문구는 에이전트와 같다 — "맨 위"·"맨 아래"·"로봇에 가장 가까운"·"로봇에서 가장 먼"·"분홍 옆"·"초록 불량 옆".
  - 작업대 그림: 위 카메라 그대로라 **그림 아래쪽이 로봇 쪽**(로봇 함수: top = v 작은 쪽 = 로봇에서 먼 쪽). "▲ 맨 위"·"▲ 로봇에서 가장 먼"은 투입 구역 위 테두리에, "▼ 맨 아래"·"▼ 로봇에 가장 가까운"은 아래 테두리에 걸친 표(맨 위·맨 아래 줄 블록을 가리지 않게. 왼쪽·오른쪽·가운데 표도 같이 위 테두리로 올림). "↔ 분홍 옆"은 위 테두리 가운데 + 투입 구역의 기준 블록(분홍이면 정상 분홍)에 점선 테두리. 그림 아래 "위치 맨 위(그림 아래쪽이 로봇 쪽)"·"분홍 옆(테두리 = 기준 블록)".
  - 결과 카드: 옮길 블록이 갈 그릇 카드(분홍·초록·불량) 오른쪽 위에 같은 문구 표(카드 색). 불량 색과 같이 오면 위치 표 아래에 불량 색 표("왼쪽" / "초록 불량"). 긴 문구는 카드 이름을 가리지 않게 낱말 단위로 줄을 바꾼다.
  - 보고서 명령 결과: "맨 위 초록 1개 · 완료"·"분홍 옆 초록 1개 · 완료"·"초록 불량 옆 분홍 1개 · 완료"·"로봇에 가장 가까운 초록 · 거부".
  - 못 읽은 위치(`target_by` = llm_none·ref_rel·llm_down·need_llm — which·next_to 없이 옴): 표 "⊘ 위치 못 읽음", 그림 아래에 이유와 낱말("LLM 도 못 읽음: 사이"·"다른 블록 기준 위·아래: 분홍 위"·"LLM 응답 없음: 끝에"), 결과 "초록 · 위치 못 읽음 · 거부". 위치 둘·색 없는 "불량 옆"도 처음부터 ⊘(에이전트가 늘 거부).
  - 로그: 의도 줄에 "위치 맨 위(규칙)"·"분홍 옆(규칙)"·"위치 로봇에서 가장 먼(LLM)", `sort_blocks` 줄·node `plan` 줄에 위치, end 줄에 `next_to`·`target_by`.
- **거부**(`status: refused`, "거부"): 할 수 없어 하지 않은 명령(위치로 고르기 못 함·배운 적 없는 동작·숫자 배치 못 함). 에이전트가 말한 이유 문구는 그대로 두고 말풍선 앞 ⊘ 와 왼쪽 띠만 주황(실패 ⚠·✗ 빨강과 구별), 로그 줄도 주황. 로봇이 실행 직전에 막은 경우(`run_policy`·`sort_blocks` 결과 `reason: refused` 바로 뒤 error, 예 "… — 팔은 그 자리(go_home 으로 홈에)")도 ⚠ 대신 같은 ⊘ 줄(끝 상태는 에이전트대로 "오류").
- **홈 자세 명령**(10-23, 에이전트 RESULT 15절): "홈으로"·"처음 자세로"·"기본 자세로 되돌려" → 그래프 "홈 자세" 칸(`home`, 불빛 = 행동). `go_home` 도구도 행동 불빛을 켠다(동작 전 홈 맞춤·동작 뒤 홈 복귀 포함). 로그 한 줄 "◀ go_home done·already_home·too_far · 집게 열기 · 한도 150°". `status: skip`(방금 홈에 갔고 그 뒤 안 움직임)은 "↷ 건너뜀"만 쓰고 불빛을 켜지 않는다. 너무 멀어 로봇이 안 움직이면(`too_far`) 로그는 주황이다. 한도 150° 로 다시 해도 안 되면 에이전트 error 가 대화창 ⚠ 로 뜬다.
- **불량 색**(10-23, 에이전트 RESULT 16절): "초록 불량 옮겨 줘"처럼 불량에 색을 붙이면(`defect_cls` = red_defect·blue_defect) 개수 카드 "불량" 오른쪽 위에 "초록 불량"·"분홍 불량" 표(그 색 칠). 색으로 고르지 못해 거부되면(로봇이 이름을 모름·ACT 방식·뺀 색만 말함 `mixed`) 점선 주황 "⊘ 초록 불량"·"⊘ 불량 색 불분명". 보고서 명령 결과 "초록 불량 1개 · 완료"·"왼쪽 분홍 불량 1개 · 완료"·"초록 불량 · 거부". 다음 명령이 오면 지운다.
- **그릇에서 꺼내기**(10-23, RESULT 16절, 리허설 초기화): "다 꺼내 놔"·"초기화해 줘"·"초록 그릇 거 꺼내 줘" → 그래프 "그릇에서 꺼내기" 칸(`unsort`, 불빛 = 행동). `unsort_blocks` 도구도 행동 불빛, 로그 한 줄 "◀ unsort_blocks real · 그릇 초록 · 블록 4 · done". 그릇이 비었으면 결과 "꺼낼 것 없음", 로봇 함수가 없으면 "⊘ 아직 그릇에서 꺼내기는 못 해요."(거부). 에이전트처럼 보고서 "명령별 소요 시간"에는 넣지 않는다. 에이전트가 꺼낸 뒤 카메라를 다시 찍지 않아 개수 카드·작업대 그림은 다음 사진 때까지 꺼내기 전 숫자 그대로다.
- **시작 로그**(`agent.get_method()`): 방식 기본 · 좌표 집기 real/mock/off · 위치로 고르기 됨(`which_values`·`next_to` 가 있으면 "됨(왼쪽·…·로봇에서 가장 먼 / 옆: 분홍·초록·분홍 불량·초록 불량)")/안 됨 · 불량 색 고르기 됨/안 됨 · 그릇에서 꺼내기 됨(실제)/됨(가짜)/안 됨(로봇 함수 없음). 옛 에이전트라 키가 없으면 그 항목은 뺀다.
- **빠른 명령 = 발표 실연 순서**(계약서 2절 끝, 10-22): ① 불량품 골라내 줘 ② 지금 배치 어때? ③ 불량 빼고 나머지 다 정리해 줘 ④ 분홍 블록 하나 내 손에 줘 ⑤ 결과 알려 줘. 멈춤은 옆의 빨간 ■ 멈춰. 그 밖의 명령(분홍·초록 옮기기 단독, 분홍 두 개만…, 문서 질문 3개, 분홍으로 숫자 1)은 "다른 명령" 에 접어 두었다.
- **숫자 배치 계획**(좌표 집기, 10-22): 에이전트의 tool `arrange_digit` 이벤트(`agent/README.md` "좌표 집기(arrange)", `layout.cells[{order,row,col,color,from_mm,to_mm}]`)가 오면 현재 배치 패널이 숫자 배치 그림으로 바뀐다. 왼쪽 = 작업대 위 블록(from_mm 을 로봇 좌표 그대로 줄여 그림, 번호 = 놓는 순서), 오른쪽 = 숫자 칸(row 0 = 위, `pattern` 의 빈 자리는 점선), 화살표 = 어느 블록이 어느 칸으로. 계획만이면(`plan_only`) 막힌 이유(`gates`), 경고 2개까지, 실행 중·뒤면 놓은 블록 수(`result.run.steps_done`)만큼 진한 칸. 끝 이벤트가 `waiting_confirm` 이면 "할까요? 응 / 아니" 와 **[응, 해 줘] [아니]** 버튼이 뜬다(버튼 = 같은 thread 로 "응"·"아니" 보내기, 말로 대답해도 됨). 다음 명령이 대답이 아니면 그림은 원래 작업대로 돌아간다.
- **계획 단계**: intent `plan` 명령이면 패널 아래에 단계 목록(✓ 끝 · ▶ 지금 · ■ 멈춤 · ✗ 실패 · ⊘ 거부 · – 건너뜀)과 단계별 개수(한 개수/예정 개수)를 보여 준다. 읽는 필드는 아래 표의 plan 줄.
- **멈춤**: 버튼, 또는 "멈춰·스톱·정지·중지·그만"이 들어간 짧은 말(10자 이하)은 실행 줄을 기다리지 않고 바로 처리한다. 에이전트 모드면 `run_command("멈춰")`(그래프 앞 규칙 경로, LLM 안 거침)를 부르고, 실패하면 `robot.run_policy.stop()`. 가짜 모드면 `fake_agent.stop()`.
- **말 → 로봇 출발 시간**: 말이 끝난 시각(녹음 끝)부터 첫 `run_policy` 시작 이벤트까지를 로그에 `말 → 로봇 출발 n초` 로 남긴다(기획서 7절 응답 속도 기준).
- 마이크는 브라우저 녹음이다: Record 누르고 말하고 Stop. 녹음이 끝나면 STT → 인식 문장을 대화창에 🎙 로 보여 주고 바로 실행한다. 조용하거나 Whisper 가 방송 자막 문구를 지어내면 버린다.
- 마이크 칸 아래 ⬆ 아이콘 = **녹음 파일 올리기**(마이크가 안 될 때·시험용). 올리면 녹음과 같은 경로(STT → 🎙 → 실행)로 가고, 끝나면 칸이 마이크 모드로 돌아온다. 미리 만든 음성은 `ui/samples/`.
- **질문 답의 근거**(10-22): 질문 답 `say` 의 `sources[].cite`("[로봇 운용 설명서 4.3]" 꼴, 에이전트 세 문서 RAG)를 말풍선 아래 작은 줄 "근거: 로봇 운용 설명서 4.3 · 함께 찾음 …"으로 붙인다. 답이 인용한 조항이 앞, 함께 찾은 조항은 2개까지. 말(TTS)로는 읽지 않는다. 문서 밖 답(`sources` 빔)은 줄 없음.
- 에이전트가 LLM·근거 조회에 실패해도 템플릿·검색 결과로 답을 이어 가는 오류(`llm:`·`citations:` 로 시작)는 대화창에 ⚠ 를 띄우지 않고 로그에 "대체 경로"로만 남긴다.
- "초기화"는 새 thread_id 로 바꾸고, `BALL_MOCK=1` 이면 에이전트의 가짜 작업대(`agent/mocks.py`)도 처음 상태(`BALL_MOCK_SCENE`: 기본 `demo4` = 발표 실연 투입 분홍 2·초록 1·불량 1, `full` = 분홍 4·초록 4·불량 3)로 되돌린다. 시작할 때 에이전트 `warmup()` 을 미리 불러 첫 명령이 빠르다.
- 명령은 한 번에 하나만 실행된다(뒤에 누른 것은 줄 서서 기다림). 멈춤·음성 인식은 실행 줄과 따로 돈다.

### 10-21 밤 4 — 받아쓰기 초기 문맥(prompt) 시험 (`docs/stt_prompt_check.md`)

- **OVMS 2026.4.1 의 `/v3/audio/transcriptions` 는 `prompt` 를 받아도 무시한다**(지금 STT = NPU). 문맥 유무로 시연 12문장 + 질문 3·잡담 2 × F1·M1 × 2번 = 68쌍이 모두 똑같이 나옴(원문 일치 36/48 → 36/48, 시간 1567 → 1563 ms). `initial_prompt`·`hotwords`·엉터리 필드(`bogus_field`)도 오류 없이 200 에 결과 같음 = 모르는 필드는 조용히 버린다. openvino_genai 라이브러리에 "'initial_prompt' parameter is not supported on NPU device" 문구가 있어, 넘겨졌다면 오류가 났어야 한다.
- **같은 모델을 openvino_genai 로 CPU 에서 직접 돌리면 문맥이 듣는다**: `initial_prompt` = “분홍 블록, 초록 블록, 불량품, 작업대, 그릇, 손, 결과 알려 줘” → 시연 12문장 원문 일치 18/24 → **23/24**("작업대"·"불량" 6건 모두 바로 나옴, 남은 하나는 M1 "골라내죠"). 문맥 낱말이 없는 질문 3·잡담 2 는 10/10 그대로, 끼워 넣기 0. 문맥이 있으면 문장부호가 빠질 뿐. 시간은 CPU 라 1회 약 4.7~5초(스레드 4·8, nice 19, 인프라 부하 시험 중이라 참고) — NPU 1.6초의 약 3배라 대시보드에 쓰지 않았다.
- 그래서 `ui/stt.py` 기본값은 문맥 끔(`STT_PROMPT=0`) 그대로, 원문 오류는 지금처럼 `FIXES` 로 바로잡는다(TTS 기준 바로잡은 뒤 24/24). 문맥을 쓰려면 Whisper 를 OVMS GPU 그래프(`graph_gpu.pbtxt`)로 돌리고 OVMS 가 `prompt` 를 `initial_prompt` 로 넘기는지 확인해야 한다(인프라 일, 아직 안 해 봄) — 넘기면 `STT_PROMPT=1` 하나로 켜진다.
