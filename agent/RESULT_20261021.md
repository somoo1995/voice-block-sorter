## 실행 (젠북, 프로젝트 루트)

- `BALL_MOCK=1 .venv/bin/python -m agent.cli --scenario` — 시연 1→5
- `BALL_MOCK=1 .venv/bin/python -m agent.cli "불량품 골라내 줘"` — 한 문장(여러 문장도 됨)
- `.venv/bin/python -m agent.eval docs/intents.csv` (`--sweep`, `--rag`)
- `.venv/bin/python -m agent.selftest` (`--offline` 은 OVMS 없이)
- UI: `from agent import run_command` → `for ev in run_command(text, thread_id)`

## 로봇 세션 추가 사항 반영

- `reason=refused` → 재시도 없이 이유를 say(studio_session·robot_busy·no_model·already_running 별 문장)하고 끝.
- `error`·`timeout` → 실패한 시도로 보고 다시 세어 1회 재시도. 성공 = `ok`(duration_elapsed) + 카메라로 정확히 1개 옮겨짐.
- `camera_released=False` → 1.5초 기다렸다 찍고, 카메라 열기 실패 시 한 번 더.
- "멈춰": 실행 중이면 `robot.stop()`, 실행 사이면 act·verify·hand_wait 가 플래그를 보고 다음 실행을 안 함.
- `timeout_s` 는 넘기지 않는다 → `robot/policies.json` 정책별 값.

**2. scene**("지금 작업대 어때?", "분홍 블록 어디 있어?")
- 흐름: detect → JSON(구역마다 한 줄 + 블록 위치 줄) → 코드가 질문 낱말로 고른 사실로 예시 답 → LLM 이 한 문장으로 다듬음 → 코드 검사 → 통과하면 LLM 답, 아니면 예시 답. 로봇은 움직이지 않는다.
- 코드 검사: 답이 말한 구역의 줄에 있는 숫자·칸만 쓸 수 있다. 예시 답의 숫자를 빼면 안 된다. 숫자를 말로 쓰거나("세 개") 어미가 깨지면 탈락이다.

**3. plan**("분홍 두 개만 옮기고 불량 골라내 줘")
- 흐름: LLM 구조화 출력 `{feasible, steps:[{intent, count}], reason}` → 코드 검증 → 실행 전에 "순서대로 할게요. 1) … 2) …" → 단계마다 기존 노드(plan·act·verify·finish, 시도마다 detect) → 끝에 계획 대비 결과.
  - 결과 예: "계획 2단계를 모두 마쳤습니다: 분홍 블록 2개(계획 2개), 불량 3개(계획 3개)."

- 코드 검증(4B 가 실제로 틀린 것마다 하나씩):
