## 2. 확인한 사실 (근거)

### 2.1 관절 목표를 직접 보내는 길

- `physicalai.robot.SharedRobot`(`robot/transport/_shared_robot.py`): `connect()` · `get_observation()` · `send_action(action, goal_time)` · `disconnect()`. `send_action` 은 "절대 관절 목표, 보내고 잊기"이다(:614). 단위는 드라이버와 같은 **정규화**(몸통 −100~100, 그리퍼 0~100).
- 정책 실행(`physicalai run`)도 이 객체를 통해 팔을 움직인다. 그래서 좌표 집기도 같은 이름(`ball-sorter-follower`)으로 붙으면 정책과 **같은 소유 프로세스·장치 잠금**을 쓴다.
  - Studio 가 팔을 쥐고 있으면 `RobotDeviceAlreadyOwned` 로 연결 단계에서 실패한다(README 2.4).
  - 구독자가 사라지면 소유 프로세스는 마지막 목표를 유지한다. 10초 뒤에는 토크를 켠 채 끝난다(README 2.2).
- 런타임(`runtime/action_sources/`)에는 `PolicySource`·`TeleopSource` 둘뿐이다. 궤적·좌표용 소스는 없다 → 실행기는 런타임을 거치지 않고 `SharedRobot` 을 직접 쓴다.
- **안전장치는 런타임 쪽에만 있다.** 소유 프로세스(`_owner_worker.py:206`)는 받은 목표를 `driver.send_action` 에 그대로 넘긴다. 속도 제한도, 관절 한계 확인도 없다.
  - 드라이버는 보정 범위로만 자르는데, follower_24 의 보정 범위가 0~4095(한 바퀴 전체)라서 사실상 자르지 않는다.
  - 서보 가속은 최대(254)로 설정된다(`so101.py:611`).
  - 그래서 실행기가 직접 해야 한다: 틱당 변화 제한, 런타임 `_return_to_initial_state` 와 같은 추종 오차 감시(움직임의 15% 넘게 못 따라오면 그 자리 유지).

### 2.2 정규화 ↔ 각도

- 드라이버: `n = (틱 − range_min)/(range_max − range_min) × 200 − 100`(`so101.py:545~560`). 홈 오프셋은 Studio 설정 마법사가 서보 EEPROM 에 써 둔다.
- follower_24 보정(Studio API 읽기)은 여섯 관절 모두 `range_min 0 · range_max 4095`이다 → **각(도) = 1.8 × n**, 0 = 범위 가운데. URDF `so101_new_calib` 의 영점 정의("각 관절 범위의 가운데", 같은 폴더 README.md)와 lerobot degrees 모드 식이 같다.
- 부호: 어깨·팔꿈치·손목 굽힘 부호 8조합 중 전부 + 만 맞다. 녹화 40개 최저점이 탁자면(z 중앙 0mm)에 모이고 시작 자세가 일정하다(표준편차 2~7mm). `config.json` `joint.sign`.
- 주의: Studio 3D 뷰어는 정규화 값을 그대로 도(°)로 넣는다(`robot-models-context.tsx:29` `degToRad(joint.value)`). 실제의 1/1.8 만큼만 움직여 보인다 → 화면으로 각도를 판단하지 않는다.

### 2.3 녹화로 본 관절 범위·집는 자세

| 관절 | 녹화에서 간 범위(도) | IK 에 쓰는 범위 |
|---|---|---|
| shoulder_pan | −55 ~ 50 | −60 ~ 55 |
| shoulder_lift | −94 ~ 75 | −99 ~ 80 |
| elbow_flex | −107 ~ 81 (URDF 한계 ±97 보다 더 감) | −112 ~ 86 |
| wrist_flex | −91 ~ 92 | −96 ~ 97 |
| wrist_roll | −32 ~ 98 | **−147 ~ 153**(URDF −10°) — 녹화 범위로는 두 집게 방향이 다 되는 곳이 좁은 띠뿐이라 넓혔다. 위에서 수직 자세라 탁자와 안 부딪힌다. 케이블 여유는 입회 확인 |

- 그리퍼(정규화): 쉴 때 50.1, 벌린 최대 61~73. 종이컵을 쥘 때 55~57 이었고, 리더는 49.4 까지 쥐었다(팔로워보다 더 → 계속 미는 상태, README 2.2 과열 줄).
- 집게 벌림 방향 = 끝 프레임 x 축이다. 움직이는 턱의 회전축이 끝 프레임 −y 이기 때문이다(URDF `gripper` 관절).
- 위에서 수직 집기가 되는 범위(`reach`, 예시 배치): 로봇 받침에서 약 110~300mm 반원. 접근 높이 50mm 에서 먼 쪽은 손목 굽힘이 녹화 범위 끝(97°)에 닿는다.

## 3. 시제품이 하는 일과 검사

- **집는 순서**: 칸마다 "놓을 때 손가락 여유"가 큰 칸부터 놓는다. 블록은 "집을 때 손가락 여유 ≥ 3mm" 중 그 칸에 가장 가까운 것을 고른다.
  - 이웃 = 아직 안 집은 블록(불량 포함) + 이미 놓은 블록.
  - 정육면체라 집게 방향은 격자 방향과 +90° 두 가지 중 닿는 것을 쓴다.
- **움직임**:
  - 홈 → 첫 블록 위: 관절 공간 한 번. 도중 링크 높이를 샘플로 본다.
  - 그 뒤: 끝을 10mm 간격 직선으로 IK. 내려가고 올라갈 때는 집게 방향을 고정한다.
  - 이동 중 손목 롤이 범위를 넘으면 90° 다른 방향으로 바꾸고 그 횟수를 센다.
- **시간**: 구간마다 max(거리/50mm/s, 관절 변화/45°/s). 집게는 0.8초, 놓은 뒤 안정 0.3초.
- **검사**(dry-run 출력 "검사"): IK 실패, 위치 오차·기울기, 관절 한계 여유, 링크 최저 높이, 집기·놓기 손가락 여유, 이동 중 방향 바꿈, 틱당 관절 변화.
- **예시 결과**(`digit 7`, 가짜 장면 = 입력 구역 15×15cm 에 55mm 격자로 정상 블록 8개):
  - 실패 0, 관절 한계 최소 여유 3.4°.
  - 약 1분 38초(블록당 14.0초, 이동 구간이 대부분), 30Hz 목표값 2,830개.
  - 경고 1: 집기 여유 최소 1.5mm. 55mm 간격이면 벌린 손가락이 옆 블록에 거의 닿는다 → 흩을 때 블록 사이를 6cm 이상 둔다.
- **자체 시험 28개**(계획 11개는 아래, 실행기 15개는 3.1 끝, 정책 뒤 복귀 2개는 README 2.3):
  - 순기구학 영점, 1.8°/단위, IK 격자 50점(최대 오차 1.4mm)
  - 호모그래피(4점 정확, 6점 1px 잡음 0.7mm), 평면 강체, 숫자 칸 수
  - 계획 실패 0, 집는 점·놓는 점 순기구학 되짚기(최대 0.4mm), 틱당 속도 한도
  - 검출 두 형식(`objects`·`detections`), 팔 끝 짚기 4점 → 로봇 위치 복원

## 9. 에이전트 도구 함수 (확정)

에이전트 연결은 에이전트 담당이 한다(총괄이 따로 맡김). 함수 형태:

```python
from robot.coord_pick.executor import arrange_digit

arrange_digit(digit: str | int, color: str = "any", dry_run: bool = True, *,
              detection: dict | None = None, small: bool = False, max_blocks: int | None = None,
              speed_deg_s: float | None = None) -> dict
```

| 인자 | 뜻 |
|---|---|
| `digit` | `"0"`~`"9"` |
| `color` | `"red"` = 분홍, `"blue"` = 초록(계약 식별자), `"any"` = 섞어서 |
| `dry_run` | `True`(기본) = 계획·시간·경고만, 로봇 안 움직임. `False` = 실제 실행 — 에이전트 프로세스에 `BALL_ROBOT=1` 이 있고 3.1절 문이 다 열렸을 때만 |
| `detection` | `detect_objects()` 결과. **dry-run 과 실행에 같은 것을 넘긴다**(없으면 함수가 위 카메라로 한 장 찍는다) |
| `small` · `max_blocks` · `speed_deg_s` | 시험용(작은 글꼴, 앞의 칸 몇 개만, 관절 속도 — 기본 15°/s, 상한 45) |

| 반환 키 | 내용 |
|---|---|
| `ok` | 요청한 것이 됐나(dry-run: 모양을 다 채우는 계획이 실행 가능 / 실행: 끝까지 놓음) |
| `mode` · `executed` | `"dry_run"`·`"real"` / 실제로 보냈나 |
| `reason` | `planned` · `refused`(문·위반·거부) · `done` · `tracking` · `stale_state` · `not_at_home` · `step_limit` · `interrupted` · `stopped` · `timeout` · `connect_refused` · `error` |
| `summary` | 말할 한 줄. 예: "숫자 7: 블록 7개, 약 3분 11초(관절 15°/s). 실패 0 · 공간 위반 0 · 경고 2" |
| `plan` | `[{order, color("분홍"·"초록"), from_mm, to_cell[행,열], to_mm}]` |
| `time_s` · `plan_time_s` · `speed_deg_s` | 실행 예상 시간 / 계획 속도(45°/s) 기준 / 관절 속도 |
| `warnings` · `failures` · `violations` | 사람이 읽는 경고 / 계획 실패(IK 등) / 작업 공간 위반 `[{kind, count, first_tick, detail}]` |
| `sim` | 가짜 로봇 모의 실행 `{ok, reason, sent, total, max_err}` |
| `run` · `run_id` | 실제 실행 감독 결과 `{returncode, stopped, timed_out, end, steps_done}` |
| `log_path` · `error` | 단계 기록 `.jsonl` / 거부·오류 이유 |

에이전트 흐름(권장):
1. "분홍 블록으로 7 만들어 줘"(intent `plan`) → `det = detect_objects()`.
2. `r = arrange_digit("7", "red", detection=det)` → `r["summary"]` 와 `warnings` 를 말한다.
   - `ok=False` 면 `failures`·`violations`·`error` 를 쉬운 말로 전하고 멈춘다(예: 블록이 모자람).
3. 사용자가 "해" 하면 `arrange_digit("7", "red", dry_run=False, detection=det)`.
   - 몇 분 걸리고 끝날 때까지 돌아오지 않는다 → `run_policy` 처럼 별도 스레드에서 부른다.
4. "멈춰" → `robot.run_policy.stop()`(정책과 같은 길, LLM 을 거치지 않음).
5. 끝나면 `detect_objects()` 로 다시 보고 결과를 말한다.

주의:
- `run_policy` 와 동시에 못 돈다(같은 잠금 → `refused`, `already_running`).
- `BALL_MOCK=1` 일 때 가짜로 바꾸는 것은 에이전트 쪽 `mocks.py` 몫이다.
- 블록 방향을 모르고 공간이 좁아서, 7·1(작은 글꼴)부터가 현실적이다(6절).

### 10.3 그릇 옮기기·홈 복귀·손목 확인

```python
from robot.coord_pick.executor import sort_blocks, go_home
sort_blocks(color="red"|"blue"|"defect"|"red,blue", dry_run=True, *, detection=None, max_blocks=None,
            speed_deg_s=None, lift_mm=0, wrist_check=None) -> dict   # arrange_digit 와 같은 키 + wrist(블록별 시도 기록)
go_home(dry_run=True, open_gripper=False) -> dict                     # 지금 자세 → home_n, 8°/s, 60° 넘게 멀면 거부
```

- **계획**: zone "input" 블록, 로봇에 가까운 것부터(이웃과 집게 여유 3mm 이상 먼저). 기울기는 0 부터 5° 씩(관절 여유 5° 이상인 첫 값). 집게 방향은 작업대 축 0°·90°, 둘 다 이웃에 닿으면 ±15·30° 비틀기. 기울인 집게 끝(닫는 도중·롤 두 갈래 포함)이 `grasp_finger` 보다 낮으면 집는 높이를 올린다. 벌린 날·손목이 금지 구역 위로 나가는 방향은 뺀다. 금지 구역(목표가 아닌 그릇·손 자리)을 지나는 이동은 `over_zone`(130mm)로 넘는다. 놓기는 그릇 위 tcp `rim_mm + release_above_mm`(70mm)에서 — 그릇 안으로 안 내려간다. 실행기는 목적지 그릇만 금지 높이에서 빼고 놓는 높이 − 30mm 까지 허용.
- **문**: sort 와 숫자 배치가 같다(BALL_ROBOT=1·확인·calibrated·계획 실패 0·공간 위반 0·금지 구역 자료·모의 실행·잠금·사전 점검·stop). 공중 리허설(`--lift-mm` ≥ 30)은 calibrated=false 여도 보낸다(r15). `go_home` 은 calibrated 를 안 본다.
- **`motion.settle_s`**: 집기·놓기 직전에 실제로 그만큼 멈춘다(16:4x 부터. 그 전엔 시간 추정에만 쓰였다).
- **손목 확인(`--wrist`, r18·r19)**: 블록마다 구간을 나눠 보낸다. 구간 사이에는 송신 프로세스가 없으므로 호스트에서 손목 카메라(icSpring)를 연다.
  1. hover(tcp 45mm 이상) → 손목 사진 → 목표 색 덩어리와 "가운데면 보일 자리"의 차이를 화면 모형으로 mm 로 → 수평 이동(한 번 25mm 까지), 4mm 안이 될 때까지 최대 3번.
  2. 내려감 → 닫기 직전 사진 → **사람이 닫기 직전 분포**(분홍 중심 (340, 154) ±40·±49px, 면적 ≥ 17,200px²) 안일 때만 닫는다. 작으면 4mm 씩 2번까지 더 내려가고, 벗어나면 한 번 다시 맞춘다. 끝내 기준 밖이면 **닫지 않는다**.
  3. 닫고 들어 올린 뒤 손목 사진이 **사람이 쥐고 들어 올릴 때 분포**(녹화 닫기 시작 0.8~1초 뒤: 분홍 (350, 262) ±50·±14px 면적 ≥ 7,404 / 초록 (375, 260) / 불량 (352, 233)) 안이면 쥔 것(r20). 사진을 못 찍으면 그리퍼 측정값이 닫힘 + 0.8 보다 큰지(16:41 실물 빈손 = 51.1). 못 쥐었으면 벌리고 홈 → 위 카메라로 다시 찾아 최대 2번 더.
  - 기준·화면 모형: `python -m robot.coord_pick.wrist fit` → `coord_pick/wrist_ref.json`. 녹화 3종 손목 영상에서 리더 그리퍼가 떨어지기 직전 프레임 153장(분홍 51: 중심 (340, 154) 면적 22,852 / 초록 51: (353, 166) 25,411 / 불량 51: (344, 142) 3,921 — 마커 때문에 덩어리가 작다). 화면 모형 = 블록이 tcp 에서 끝 좌표 (dx, dy, dz) 떨어졌을 때 덩어리 중심 회귀(접근 프레임 988점, 블록 위치 = 사람이 닫기 시작한 순간의 tcp — 상대 FK 라 보정 오차 없음). 잔차 중앙 27px(약 11mm), 교차 검증 32px. 대략 u ≈ −2.3px/mm × dy, v ≈ +2.5px/mm × dx. 핀홀 모형은 맞지 않았다(잔차 29~45px, 매개변수가 한계에 붙음).
